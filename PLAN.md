**Окружение.** Windows 11, MSYS2. Основной bash 5.2.37 = `bash` в PATH. Второй bash 5.3.9 (cygwin): `C:/bin/msys64/usr/bin/bash.exe`; наборы на нём запускать ТОЛЬКО так: `PATH="/c/bin/msys64/usr/bin:$PATH" /c/bin/msys64/usr/bin/bash.exe tests/tests.sh` — без префикса PATH дочерний `bash` раннера оказывается msys 5.2 и набор сообщает 0 тестов. `python` в PATH — заглушка Microsoft Store, зависает; использовать perl/awk/sed. Мастер-свип: `bash kbool/tests/tests.sh` (≈8–9 мин на версию; 20 наборов). Два набора/два bash — строго последовательно (гонка на `tests/.ckk` и `/tmp`). Итог смотреть grep-ом по ВСЕМ строкам `[FAIL]`, не по хвосту. Бенчи: `bash kcl/<unit>/bench.sh` там, где есть; правило — ни одна метрика не хуже; не перечислять таблицу функций большого шелла (`compgen -A function`) — замедляет весь процесс.

**Контракты kklass (актуально после kklass `b564029`, 2026-09-05).** `func` возвращает через `kk._return V` → `$RESULT`; direct-вызов НЕ печатает, под `$()` печатает ровно один раз; вычисляемые свойства — так же (D1 kklass). Статические методы со static-свойствами теряют состояние под `$()` — значение и в `REPLY`. Инстанс = `<inst>_data` + `<inst>_class` + обёртки `<inst>.<член>()`; `.delete` освобождает только это — дополнительные массивы юнита (`${inst}_items` и т.п.) освобождает деструктор юнита. Зарезервированные имена членов: `this __inst__ __class__ RESULT REPLY IFS __kk_*`. `inherited`/`.parent` — от класса-владельца тела; `.call` виртуальный. Fork в горячем пути = 1–16 мс на большом шелле.

**Уточнение X-SETE (владелец, 2026-09-06, проверено на 5.2.37 и 5.3.9).** Сплошное преобразование 143 `[[ … ]] && …` **отменено**: предпосылка была неверна. bash завершает скрипт только для команды, следующей за **последним** `&&`/`||`; упавший левый операнд из-под `set -e` не роняет. Идиома debug-лога `[[ "${VERBOSE_KKLASS:-}" == "debug" ]] && echo … >&2` перед `return 1` благополучно доходит до `return 1`. Живая проверка: `set -e; TList.new L; L.Get 5 || echo reached` печатает `reached` на обеих версиях. Рвут `set -e` только две формы, обе названные планом изначально:
1. **Хвостовой список** — последняя инструкция функции. Скан всех 17 юнитов дал 3 попадания, и все три — намеренные rc-предикаты (`dateutils._two`/`_three`, `TSet._isSet`), у которых **каждое** место вызова уже под `|| return 1` или `if !`. Правок не потребовалось.
2. **Голая команда, у которой rc и есть ответ.** Найдено контракт-тестами, а не чтением кода: компаратор в `TArray._cmp3` и в цикле слияния `sort`, `TStringList._sortcmp`, голый `[[ =~ ]]` в `TRegEx._match1`. Все четыре теперь захватывают статус через `|| rc=$?`.
Плюс голая арифметика: `(( x++ ))` даёт 1 при нуле, `(( n -= 1 ))` — при результате 0, поэтому `+= 1` из плана лечит только половину; единая идиома `(( … )) || :` на 30 мест, записана в контракт `README.md` §1.4. 1. **Парсер — восемь обычных функций `tca._*`, а не члены kklass.** Они получают массив данных инстанса по имени, поэтому не стоят диспетчеризации, не могут напечатать в `$( )` вызывающего (ради чего и существовал `kk.call_silent`) и тестируются напрямую. Публичные члены остались тонкими; ответы помощников ходят в четырёх приватных глобалах `__TCA_*`, а не в RESULT.
2. **FindOptionIndex принимает ПАРУ (short, long).** У FPC одно имя на вызов плюс `var LongOpt`, а композицию делают вызывающие; порт носит пару через весь API. Пустое имя = «не задано» и не ищется — FPC ради этого передаёт невозможный символ `#255`.
3. **GetOptionAtIndex сделан публичным** (в FPC он `protected`): после слияния (short, long) вызывающий не знает, какая форма совпала.
4. **GetNonOptions отвечает rc 1** там, где FPC поднимает `EListError` (D2), и не трогает выходной массив. Следствие для вызывающих: строка с одиночным `-`, серединным `--` или неизвестной опцией теперь ПАДАЕТ, а не считает их не-опциями.
5. **GetOptionValues возвращает значения в порядке FPC — ОБРАТНОМ порядку командной строки** (следствие скана вниз, TCA-17/R10). Верно по исходнику и достаточно неожиданно, чтобы про это писали и README, и тест; отмена — две петли.
6. **`CheckOptions` в FPC читает ЗА КОНЦОМ строки кластера.** `O:=O[j]` укорачивает `O` до одного символа, а цикл продолжает индексировать `O[j]` по ИСХОДНОЙ длине; `-cv` со спецификацией `c::v` попадает туда даже без ошибки. Порт сохраняет строку скана целой и запоминает «потребившую» опцию в отдельной переменной — для любого входа, где FPC остаётся в границах, поведение идентично. 7. **Location — без хвостового разделителя** (FPC `ExtractFilePath` его оставляет) и `.`, если у `$0` нет каталога: как `tpath.getDirectoryName` и весь остальной kcl.

9. **Умолчания конструктора оставлены прежними** (`StopOnException=true`, `ExceptionExitCode=1`, `Title='Application'`; у FPC — `False`, `0`, `''`). Ни одна находка их не трогала; записаны в раздел «Differences from FPC» README юнита.

12. **Найдено вне фазы, НЕ исправлено** (`kcl_ledger.json`, `found_in_P4`): (а) **kklass** — чтение ХРАНИМОГО (`var`) свойства под `set -u` роняет вызывающего: `kk._property`/`kk._prop_plain` проверяют `[[ "$4" == "=" ]]` на отсутствующем параметре. Там, где FPC клампинг ДЕЙСТВИТЕЛЬНО определяет (`Copy`/`Delete`, то есть `substring`/`remove`), он сохранён без изменений и закреплён отдельными пинами в 027.

6. **Диапазон целых проверяется, а не молча усекается.** FPC `Val` принимает десятичный литерал до Int64 и даёт компилятору усечь его в тип назначения, а не-десятичный — до 2⁶⁴−1 с расширением знака. ## 4. Правило для тестов: сначала красный

Каждая находка из `REVIEW.md` получает регрессионный тест с её ID в имени или в `kt_test_start`. Порядок обязателен:
1. тест пишется **до** правки и запускается на текущем коде — он обязан **упасть** (если не падает, тест переписывается, а не правка откладывается);
2. затем правка, тест зеленеет;
3. в леджере у находки фиксируется имя теста.

Системно переписываются слабые ассерты (REVIEW.md §3): `$? -eq 0` → сравнение значения; «любой из двух ответов» → один ответ; `*a*`-подстроки → точное равенство; `if ParamCount>0` и подобные гварды убираются; безусловные `kt_test_pass` удаляются; symlink-probe в tfile переводится на существующую цель, чтобы 12 «PASS (skipped)» стали настоящими тестами. В каждый набор добавляется `NNN_Contract.sh`: загрузка под `set -eu`, инъекционный индекс, значение `-n` через `$()`, освобождение всех `${inst}_*` после `.delete`, не-ASCII перед искомым символом там, где есть строки. Перф-стенки закрываются относительными гейтами (например, 800 append < 10× 200 append), а не миллисекундами.
