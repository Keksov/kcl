## Правила работы
- **Сначала красный.** На каждую находку из REVIEW.md пиши регрессионный тест с её ID в имени/описании ДО правки и запускай на текущем коде: он обязан упасть. Если не падает — переписывай тест, а не откладывай правку. Потом правка, тест зеленеет, имя теста фиксируется у находки в леджере. Слабые ассерты (`$? -eq 0`, «любой из двух», подстрока, ветки под `if ParamCount>0`, безусловный `kt_test_pass`) переписывай по ходу.
- **Гейт каждой фазы:** набор(ы) юнита 0 FAIL на 5.2 и 5.3; мастер-свип `bash kbool/tests/tests.sh` 0 FAIL на обеих; бенчи не хуже; смоук `set -eu`; `git status` чистый после свипа; `.ckk` и `/tmp` не растут.
- **Коммиты только по явной команде владельца** («go», «коммить»). Сабмодуль kcl (и kklass/kkore/ktests, если трогал) коммитить раньше родителя kbool; push отдельно и тоже только по команде. thashset прошёл P1 своего роадмапа и закоммичен вместе с P2 (kcl `6d983e9`); его собственные P2–P4 (алгебра множеств, события, бенч+docs) ещё впереди — вне своей фазы юнит не трогать.
- После каждой фазы: обновить `kcl_ledger.json` (status, gate, tests, notes), затем короткий отчёт владельцу и ожидание «go» на следующую фазу. Не переходить к следующей фазе без «go».
- Если находка при воспроизведении не подтверждается — отметь в леджере как `not-reproduced` с командой, не «исправляй» вслепую.
- Отчёты владельцу — по-русски, коротко, с числами тестов и фактическим выводом при неудачах.
