# kcl/fv.unicode — the character table of the fv.* text UI

The width and the cluster role of every Unicode code point, for the screen
buffer of [`fv.video`](../fv.video/README.md) (decision D5 of the
[plan](../docs/dev/fv/PLAN.md): CJK and emoji take 2 columns, combining marks
0). A port in spirit of FPC rtl-unicode `eastasianwidth` and the width part of
rtl-console `video.pp` (`ExtendedGraphemeClusterDisplayWidth`): **plain
functions, no classes, no forks, no locale dependence** — code points (integers)
in, ASCII letters out. The table is **Unicode 16.0.0 with the glibc 2.41 width
rules**, generated by [`tools/unicode`](../../tools/unicode/README.md) into a
block of `fv.unicode.sh`. The unit loads no other unit.

## Quick start

```bash
source /path/to/kbool/kbool.sh
kk.uses fv.unicode

fv.unicode.charWidth 19968;  echo "$RESULT"    # U+4E00 一 -> 2
fv.unicode.charWidth 769;    echo "$RESULT"    # U+0301 combining acute -> 0
fv.unicode.charClass 128512; echo "$RESULT"    # U+1F600 😀 -> y (wide, Extended_Pictographic)
printf -v cp '%d' "'ж"; fv.unicode.charWidth "$cp"   # from a character (UTF-8 locale; see below)
```

## API

| Function | Answer |
|---|---|
| `fv.unicode.charClass CP` | `RESULT` = the class letter of code point CP (table below) |
| `fv.unicode.charWidth CP` | `RESULT` = its width in cells: 0, 1 or 2 |
| `fv.unicode.version` | `RESULT` = `16.0.0`, the Unicode version of the table |

CP is a **decimal** integer 0..1114111 (1–7 digits, leading zeros allowed:
`0000065` is `A`). Not digits (`''`, `x`, `-1`, `+65`, `0x41`, a space, 8 or
more digits) → rc 2; above U+10FFFF → rc 1; `RESULT=''` on both, one `Error:`
line under `VERBOSE_KKLASS=debug`. Surrogates (U+D800..DFFF) and controls are
answered like any code point (`n`): the callers never pass them (fv.video stores
them as `?`).

| Class | Width | Meaning | Examples |
|---|---|---|---|
| `z` | 0 | zero width: extends the cell before it | U+0301, U+200D ZWJ, U+FE0F VS16, U+1160 Hangul jungseong, U+E0020 tag |
| `n` | 1 | narrow | `A`, `é`, `ж`, `─` U+2500, U+0600 |
| `w` | 2 | wide | `一` U+4E00, `가` U+AC00, `Ａ` U+FF21, U+3000 |
| `x` | 1 | narrow, Extended_Pictographic | `©` U+00A9, `❤` U+2764 |
| `y` | 2 | wide, Extended_Pictographic | `⌚` U+231A, `😀` U+1F600 |
| `m` | 2 | emoji modifier U+1F3FB..1F3FF | 🏽 (extends an `x`/`y` base) |
| `r` | 1 | regional indicator U+1F1E6..1F1FF | 🇦 (two make one flag cell of width 2) |

The cluster roles (`z`, `m`, `x`/`y`, `r`) are for fv.video's cell rules: a
zero-width character joins the cell before it, a modifier joins an
Extended_Pictographic base, a ZWJ joins the next character only when that one is
Extended_Pictographic, and two regional indicators make one flag. The widths
here are per code point; those cluster rules (and the choice for VS16 after a
narrow base) belong to fv.video.

**The letters are all lower case and distinct in any case, on purpose:** a
caller's `nocasematch` (which bends `case` and `[[ == ]]` patterns) can never
make one class match another — `x` next to a capital letter for the wide
pictographs would have. `charWidth` maps a class through an associative array
(an exact key lookup), not a pattern.

## The width rules (glibc 2.41)

In this order (glibc's `localedata/charmaps/UTF-8` header, checked against the
charmap of the lab VM's glibc 2.41):

| Rule | Width |
|---|---|
| U+00AD SOFT HYPHEN | 1 |
| U+115F HANGUL CHOSEONG FILLER | 2 |
| U+3248..U+324F (circled numbers on black squares; East_Asian_Width A, but glibc's table has them 2) | 2 |
| Hangul_Syllable_Type V or T (U+1160..11FF, U+D7B0..D7FB: medial vowels and final consonants) | 0 |
| General_Category Mn or Me | 0 |
| Default_Ignorable_Code_Point (ZWJ, ZWSP, VS, tags, U+3164 HANGUL FILLER, …) | 0 |
| East_Asian_Width W or F (the explicit lines of `EastAsianWidth.txt`) | 2 |
| everything else (A = ambiguous is 1, so box drawing stays 1) | 1 |

So a visible format character such as U+0600 ARABIC NUMBER SIGN is 1 (it is Cf
but not default-ignorable), and a Hangul syllable written as jamo L + V + T
takes 2 + 0 + 0 cells, like the precomposed syllable. `tests/004` compares
`charWidth` with glibc's `wcwidth()` for every code point glibc knows (292 464 in the
lab VM, 2026-11-11): no difference. Code points glibc does not list (`wcwidth` −1: unassigned, controls,
surrogates) get what the data gives them: unassigned code points that
`EastAsianWidth.txt` lists as W (the reserved parts of the CJK blocks and of
planes 2 and 3) are 2, unassigned default-ignorables (U+E0000..E0FFF) 0, the
rest 1. `@missing` lines and the header's prose defaults are not applied, as in
glibc.

**Version:** 16.0.0 is the version glibc 2.41 (Debian 13) uses; regenerating
for another version is one run of the generator (`--version`). Terminals carry
their own tables and may differ on emoji and on the newest characters; fv.video
re-positions the cursor after such cells, and `tools/termcheck` measures a
sample per terminal.

## From a character to a code point

`printf -v cp '%d' "'$c"` gives the code point in a UTF-8 locale on Linux,
macOS and BSD. **On Cygwin-based bash (Git-bash, MSYS2, Cygwin) a character
past U+FFFF is two bash characters** (`${#c}` is 2, a substring can cut it into
3 + 1 bytes) **and `printf %d` gives its high surrogate** (55357 for 😀), on bash
5.2 and 5.3 alike; decode its four bytes in the C locale instead. fv.video does
this for its writes; this unit takes only the number. (In musl's C locale,
Alpine, `printf %d` of a byte ≥ 0x80 gives 0xDF00 + the byte: take `& 255`,
or only the low bits a UTF-8 decode uses.) The number is checked against
`[0123456789]`: `[[:digit:]]` also matches other scripts' digits on macOS and
FreeBSD.

## The table

The generated block (`# BEGIN GENERATED` … `# END GENERATED`, never edited by
hand) records the version, the five input URLs and their sha256 — no date, so
the same inputs always give a byte-identical file — and holds:

* `__FV_UC_P` — 68 strings of 64 letters, one letter per page of 256 code
  points: the class all its code points share, or `*` for a mixed page;
* `__FV_UC_M[page]` — the 256 letters of each of the 110 mixed pages,
  run-length coded (`n169x1n4x1n81`);
* `__FV_UC_E` — filled at run time: the first lookup on a mixed page expands it,
  16 letters per element (index = CP >> 4); `__FV_UC_EV` records the table
  version the cache was built from, and a reload (`kk.unit --forget` + `kk.uses`)
  of a table with another version drops the cache;
* `__FV_UC_W` — class → width.

Short strings in arrays, not one long string: bash's substring of a long string
walks it character by character in a UTF-8 locale (a 4352-letter string cost
~20 µs per lookup), and 68 elements load in a third of the time of one element
per page. A lookup is a page letter, and for a mixed page a 16-letter chunk.

## Cost

Fork-free on every path (`tests/002`: `PATH=''` and the static scan). Median of
5, 2026-11-11, the machine in use:

| measure | MSYS2 5.3.9 | Cygwin 5.2.21 | VM 5.1.16 | VM 5.2.37 |
|---|---|---|---|---|
| `kk.uses fv.unicode` in a fresh shell | 7.0 ms | 8.2 ms | 5.0 ms | 5.7 ms |
| … for comparison `kk.uses fv.mouse` | 8.3 ms | 8.1 ms | — | — |
| the generated block alone (warm `source`) | +1.0 ms | +1.0 ms | — | — |
| `charClass`, uniform page | 18–25 µs | 19–25 µs | 24 µs | 32 µs |
| `charClass`, mixed page (expanded) | 27–33 µs | 27–32 µs | 32 µs | 38 µs |
| the first lookup on a mixed page (its expansion) | 85–120 µs | ~110 µs | 73 µs | 134 µs |

About 6 µs of a call is bash's function call and ~9 µs the argument check.
Forms measured and rejected: one long string of 4352 letters (+20 µs per
lookup), one array element per non-`n` page (825 elements: the same lookup
cost, +3.3 ms load), all mixed pages expanded at load (+2 ms load), a binary
search over 1087 range starts (73–92 µs per lookup).

## Contract (kcl README §1) and deviations

§1; deviations: plain functions, not a class; **nothing is printed, also inside
`$( )`** (the answer is `RESULT`: the unit is called from fv.video's writes,
which may run inside a caller's `x=$(…)`); a malformed argument is rc 2 and a
code point above U+10FFFF rc 1, both with `RESULT=''`. Globals: `__FV_UC_*`.
The first lookup on a mixed page fills `__FV_UC_E`; inside a subshell that
expansion stays in the subshell (harmless: the next lookup expands again).
